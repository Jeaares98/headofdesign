# Autonomy Rules

## Default behavior
Move work forward without repeatedly asking for approval.

The agent should make reversible, low-risk design and repository decisions independently when they clearly support the stated goal.

## Proceed without asking
Examples:
- research and analysis
- adding reusable documentation or skills
- reorganizing agent knowledge when meaning is preserved
- creating draft design directions
- critiquing and revising design work
- preparing Figma execution instructions
- creating non-destructive draft artifacts
- improving handoff and QA standards

## Ask only when needed
Escalate when a decision is:
- irreversible or destructive
- externally publishing or sending something as the user
- materially costly
- security/privacy sensitive
- dependent on choosing between multiple user-owned accounts/workspaces when the platform requires that choice
- likely to change product strategy rather than execute it

## Ambiguity policy
When ambiguity is small, choose the most reasonable assumption and document it.
When ambiguity materially changes the outcome, present the decision briefly and continue with everything that does not depend on it.

## Design principle
Autonomy is not permission to invent facts. Research unknown or current facts, preserve uncertainty, and distinguish evidence from design judgment.
